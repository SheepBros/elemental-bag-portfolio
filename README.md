## 프로젝트 요약

보드게임의 유명한 메커니즘인 **백빌딩** 메커니즘을 전투 중심으로 재해석한 로그라이크 개인 프로젝트 입니다.

플레이어는 매 턴 룬을 가방에서 뽑아 자원을 획득하고,
획득한 자원을 통해 스킬을 사용해 적을 물리쳐야 합니다.

룬을 연속으로 드로우 하는 것은 더 많은 자원을 얻을 수 있지만,
위험한 룬을 뽑아 행동 불능에 걸릴 수도 있기 때문에 플레이어는 그 사이의 간극을 잘 조절해야 합니다.

## 프로젝트에 대해

이 프로젝트는 한 명의 개발자가 AI를 사용해 게임 아이디어를 실제 프레이 가능한 제품 형태까지 구체화하고 출시까지 할 수 있는지를 검증하기 위해 시작했습니다.
최종적으로는 실제 스팀까지 데모 버전을 출시하여 유저와의 소통을 통해 피드백을 쌓는 과정 경험하는 것을 목표로 하고 있습니다.

기존 상용 프로젝트에서는 주어진 팀 구조와 콘텐츠 안에서 개발했다면,
이 프로젝트에서는 아래 범위를 직접 결정하고 연결했습니다.

- 전투 규칙과 성장 구조 설계
- 룬 / 스펠 / 유물 / 적 / 이벤트 콘텐츠 구조
- 세션 진행과 보상 흐름
- 데이터 파이프라인
- Runtime / UI 경계
- UI/UX와 연출
- 로컬라이제이션 대응
- 릴리스 가능한 데모 범위 정의

## 프로젝트 사용 스킬

- 엔진: Unity 6
- UI: UGUI, TextMeshPro
- DI/Async: VContainer, UniTask
- Data: Excel, Luban
- AI: GPT, Codex (5.6 ~ 6)

## 개발 사례
개발하면서 작업한 일부를 사례로 소개 드립니다.

### 의존성 주입 — VContainer
초기 전투 프로토타입에서 기능이 늘어나면서 전투를 구성하는 객체도 빠르게 증가했습니다.
레퍼런스였던 슬레이 더 스파이어 게임처럼, 랜덤 시드 기반에 결정론적인 플레이 흐름, 리플레이 기능 같은
제대로 된 아키텍처 아래에 구현되어야 하는 기능들을 고려해서.
나중에 여러 시스템들이 나중에 추가 되어도 코드 관리에 문제가 없도록, VContainer을 도입했습니다.

```text
Scene
  ↓
LifetimeScope
  ↓
BattleSession
  ├─ BattleFlow
  ├─ Token Bag / Resource
  ├─ Spell / Enemy Action
  ├─ Battle Result
  ├─ Presentation
  └─ UI Presenter
```

현재 전투에서는 `BattleLifetimeScrope`가 전투에 필요한 서비스를 등록하고, 실제 전투 진행은 `BattleSession` 이후의 각 시스템이 담당합니다.

**결과**
- LifetimeScope에서 생성과 연결을 담당
- 각 시스템은 필요한 인터페이스에 의존
- 전투 / 세션 단위 lifetime 관리
- 테스트 및 기능 교체 시 의존 관계 추적이 쉬워짐
- AI Agent 사용에 있어서, 복잡하지 않고 관리가 쉬운 구조 구축

### 컨텐츠 데이터 파이프라인 — ScriptableObject -> Excel/Luban

초기 전투 프로토타입에서는 빠른 개발 및 테스트를 위해 정적 데이터를 Unity의 ScriptableObject 기반 데이터로 관리했습니다.
추후 프로토타입 확인이 끝난 후, 전투뿐만 아니라, 룬, 스펠, 유물 아이템, 적, 이벤트, 보상 등의 여러 복잡한 데이터를 관리하기 위해
엑셀 기반의 데이터 테이블 관리를 시작하고, Luban 이라는 플러그인을 통해 데이터 코드 및 bytes데이터를 생성&관리 하는 기반을 구축했습니다.

```text
Excel
  ↓
Luban
  ├─ Generated C#
  └─ Generated Bytes
```

**결과**
- Excel 데이터 화를 통해 관리를 용이하게 함
- Id 기반 콘텐츠 연결
- Generated data와 런타임 상태 분리
- Codex가 Luban 시스템을 익혀, 이를 통한 대량 콘텐츠 작성 / 수정 / 검증이 쉬운 구조
